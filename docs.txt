# ScoutWay — Travel Story Sharing App
### Full-Stack Project Documentation (MERN + Tailwind CSS)

---

## 1. Project Overview

**ScoutWay** is a full-stack travel journaling and story-sharing platform. Users can log in (or continue as a guest) and browse travel stories shared by everyone on the platform — similar to an open-source feed. Any registered user can add their own travel story, including the trip name, destination, travel dates, a day-by-day activity thread with costs, and a written narrative with a cover photo. All published stories are publicly visible to every user.

**Core idea:** *"Journal your trips. Discover everyone else's."*

## 3. User Roles

| Role | Capabilities |
|---|---|
| **Guest** | Browse/read all public stories. Cannot post, like, or comment. Prompted to sign up when attempting a restricted action. |
| **Registered User** | Browse stories, add/edit/delete own stories, like stories, search/filter stories. |

## 5. Data Models

### 5.1 User
```json
{
  "_id": "ObjectId",
  "name": "String",
  "email": "String (unique)",
  "password": "String (hashed, null if Google/guest)",
  "authProvider": "local | google | guest",
  "googleId": "String (optional)",
  "avatar": "String (URL, optional)",
  "createdAt": "Date"
}
```

### 5.2 Story
```json
{
  "_id": "ObjectId",
  "userId": "ObjectId (ref: User)",
  "title": "String",              // e.g. "Adventure in the Amazon Rain Forest"
  "place": "String",               // e.g. "Amazon Rainforest, Brazil"
  "tripStartDate": "Date",
  "tripEndDate": "Date",
  "coverImage": "String (URL)",
  "description": "String",         // main story text
  "activities": [
    {
      "activityName": "String",    // e.g. "Boat ride into the jungle"
      "cost": "String"             // numeric value OR "-" if unknown
    }
  ],
  "likes": ["ObjectId (ref: User)"],
  "isPublic": "Boolean (default true)",
  "createdAt": "Date",
  "updatedAt": "Date"
}
```

> **Note on cost field:** Since users may not know/remember the cost of every activity, store `cost` as a **String** rather than Number, defaulting to `"-"`. Handle numeric parsing/formatting only when a valid number is entered (e.g., for totals or analytics).

## 6. API Endpoints

### Auth
| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/auth/register` | Register new user |
| POST | `/api/auth/login` | Login with email/password, returns JWT |
| GET | `/api/auth/google` | Initiate Google OAuth |
| GET | `/api/auth/google/callback` | Google OAuth callback |
| POST | `/api/auth/guest` | Create/assign temporary guest session |
| POST | `/api/auth/logout` | Logout / clear session |
| GET | `/api/auth/me` | Get logged-in user profile |

### Stories
| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/stories` | Get all public stories (supports query params: `search`, `startDate`, `endDate`) |
| GET | `/api/stories/:id` | Get single story detail |
| POST | `/api/stories` | Create new story (auth required) |
| PUT | `/api/stories/:id` | Update story (author only) |
| DELETE | `/api/stories/:id` | Delete story (author only) |
| PATCH | `/api/stories/:id/like` | Toggle like on a story (auth required) |
| POST | `/api/stories/:id/image` | Upload/replace story cover image |

---

## 7. Authentication Flow

1. **Local (email/password):** Register → password hashed with bcrypt → stored in DB. Login → compare hash → issue JWT → stored in httpOnly cookie or localStorage.
2. **Google OAuth:** Use `passport-google-oauth20` on the backend. On success, find-or-create user by `googleId`/email → issue JWT.
3. **Guest mode:** No credentials required. Backend issues a short-lived JWT with `authProvider: "guest"` and read-only permissions (frontend disables Add/Edit/Delete/Like buttons and redirects guest to Register when attempted).
4. Protect story-mutation routes (`POST`, `PUT`, `DELETE`, `PATCH /like`) with middleware that verifies JWT and checks `authProvider !== "guest"`.

## 9. UI/UX Notes (matching your mockups)

- **Color palette:** Deep navy/teal (`#0F3D5C`–ish) for headings and primary buttons, light aqua/mint background (`#EAF6F7`-ish) for page backgrounds, white cards with soft shadows.
- **Typography:** Bold, rounded sans-serif for headings (large display type on landing page); clean sans-serif for body text.
- **Cards:** Rounded corners, subtle shadow, heart icon top-right for likes, image top, text content bottom.
- **Calendar:** Reusable component appearing both on the feed page (as a filter) and can double as a date-range picker inside the Add Story form.
- **Consistent components:** The same `Login` panel design (image left, form right) should be reused for Register.
